# Simplicity Rules

- 10 lines > 50 lines
- 1 function > 4 unnecessary functions
- existing utility > new utility
- direct solution > abstraction
- small diff > massive rewrite
- working code > fancy code

No classes, interfaces, design patterns, abstractions, or dependencies without a concrete reason.

If a problem can be solved cleanly in one function, use one function. If it can be solved by modifying one existing file, modify one file.
